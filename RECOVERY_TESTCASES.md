# m75 recovery, case by case

Every JSON test case engine **m75** is measured on, showing the corrupted input it was given and the JSON re-rendered from the AST it produced. Generated by `dart/experiments/recovery/_render75.dart`; do not edit by hand.

## How to read a case

```text
in   the mutated input, character for character, unchanged
mut  ^ marks the character(s) the corruption touched, or, for a deletion, the
     boundary the deleted character was removed from (known by construction,
     not recovered by search)
m75  ~ marks input m75 found unusable; v marks a boundary where the grammar
     wanted a symbol the input never supplied, and a digit marks a boundary
     where it wanted that many
ast  the JSON re-rendered from the repaired AST
```

The `ast` line is **not** the input echoed back. Structural punctuation on that line -- `{` `}` `[` `]` `,` `:` -- is emitted by the *grammar*, from the shape of the recursion tree. Everything else is the literal input text of the span each node covers. So where `ast` differs from `in`, the difference is exactly the reshaping that recovery performed.

Three annotations can appear inline in `ast`:

| marker | meaning |
|---|---|
| `<?>` | The grammar demanded a symbol at this point and the input did not supply one. The tree holds a **zero-width** `SyntaxError` here. m75 does not write which symbol was wanted, because a wide character class cannot say which member it would have been -- picking one would be invention, not evidence. |
| `<!text!>` | Input the grammar could not give a role to, shown verbatim. The tree holds a `SyntaxError` span covering exactly these characters. |
| `String(…)` | A terminal that carries a marker is named, because a terminal missing its own delimiters cannot be identified from its text: `<?>2[,33,true]<?>` on its own could be anything, and `String(<?>2[,33,true]<?>)` says the AST read those eleven characters as a string with both quotes absent. Terminals that read cleanly are not named. |

Because the AST is built over the **original, unchanged** input (I32), no node on the `ast` line can claim text the document did not supply. That is machine-checked in `_tree75.dart`: putting every leaf back to the pure parser at its own position over the untouched input, m75 places **0** unsupported nodes across this battery, where m74 places 535.

### Renderer self-checks

| check | what it rules out | result |
|---|---|---|
| REPLACED | an input character silently dropped by the renderer rather than by the grammar: every character not emitted verbatim and not shown inside `<!…!>` must be structural punctuation or whitespace | **pass**, 0 cases |
| MARKS | a marker invented by the renderer, or a tree error node it failed to show: inline marker count must equal the `SyntaxError` node count in the tree | **pass**, 0 cases |
| ROUND-TRIP | recovery disturbing input that was already valid: for every input that already parses -- the 7 controls, and L11, whose `Q` happened to land inside a string, 8 in all -- the re-render must itself parse and must carry no markers | **pass**, 0 cases |
| OVERDRAW | a boundary mark sitting inside a span mark on the `m75` line, which would draw the `~` run one character short | **pass**, 0 columns |

> On the shape column: the battery is built by corrupting one known document, so "recovers the original shape" rewards *guessing the document back*, which is the invention the brief forbids. On all 43 battery inputs where m74 matches the original shape and m75 does not, m74 buys the match with at least one node the input does not support; there are 0 inputs the other way. The number is reported here for continuity with the engine table, not as a target.

> Not included: the five non-JSON probe grammars (`'a'* "ab"`, `('a' / "ab") 'b'`, `A <- 'a' / "ab"`, `'a'? "ab"`, `&(A 'b') A 'b' 'x'`) used by `_m75diff.dart` and `_subset75.dart`, and the LR/RR expression-grammar depth ladders. Those are not JSON, so there is no JSON to re-render; they are scored on cost against exhaustive truth instead.
